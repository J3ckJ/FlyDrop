# Пульт

iPhone управляет Mac и Windows в своей Wi-Fi и отправляет файлы в FlyDrop. Здесь два клиента и один агент.

1. **PWA** — основной клиент. Его отдаёт агент по HTTPS, как FlyDrop отдаёт свой веб-клиент. Открывается в Safari и ставится на экран «Домой».
2. **Приложение SwiftUI** — тот же протокол, плюс настоящие Live Activity (ActivityKit) и виджеты экрана блокировки (WidgetKit).

Интерфейс на русском и повторяет макет `design/WHATS_NEW.md`: чёрный фон, стекло только у поиска, таб-бара, плавающих кнопок и шторки. Зелёный — компьютер в сети, янтарный — спит, синий — идёт передача, красный — только «Выключить».

## Как устроено

На Windows Пульт — один файл `pult.exe`. Его запускают двойным щелчком, как TeamViewer или AnyDesk: в командной строке обычный exe, родитель — проводник, без `node`, без `.js` и без PowerShell. На macOS и в демо `--mock` остаётся агент Node.js 22, тот же runtime, что у FlyDrop.

- Управление идёт по WebSocket `wss://компьютер:4720/pult` поверх TLS-сертификата (ECDSA P-256, только частные IPv4 и localhost). Сертификат ставится заранее по обычному HTTP `http://компьютер:4721/setup`: Safari открывает его до доверия. На 4721 нет управления и нет файлов, только профиль и `/ping`.
- Кадр экрана — отдельное бинарное сообщение: байт `0x01`, длина JSON-заголовка, `{seq,width,height}`, затем JPEG. Не больше 12 кадров/с.
- Обнаружение — объявления mDNS `_pult._tcp.local`. В TXT нет кода сопряжения, только ОС, версия, короткий отпечаток и порт FlyDrop.
- Сопряжение — шесть цифр на экране компьютера, один раз. После успеха код меняется. Пять ошибок с одного адреса за минуту останавливают попытки. Ключ телефона хранится как SHA-256.
- Несопряжённый сокет может только представиться и ввести код. Адрес вне локальной сети (и CGNAT `100.64.0.0/10`) соединение не получает.
- Выключение принимается только с `hold: true`. Если FlyDrop ещё передаёт файл, выключение и перезагрузка не выполняются, пока телефон не пришлёт `force: true`.
- Общий разбор команд лежит в `protocol/` и проверяется `swift test` на Linux. Тот же набор команд проверяет агент.

FlyDrop не переписан. Агент встраивает `createApp` из корня репозитория. Если порты 4317/4318 уже заняты живым FlyDrop, агент не поднимает второй и не подтверждает устройства сам: телефон нужно подтвердить в окне FlyDrop. Пока FlyDrop внутри Пульта, агент держит получателя «в сети» и подтверждает телефон только если запрос пришёл с адреса уже сопряжённого Пульта.

PWA не может сама выставить заголовок `Origin` на чужой порт, а FlyDrop требует его. Поэтому загрузка из PWA идёт на `/api/upload` того же сайта, а агент пересылает тело в FlyDrop. Нативное приложение говорит с FlyDrop напрямую: код и `hostId` приходят в `hello` после сопряжения.

На Windows `pult.exe` двигает мышь и клавиатуру (`SendInput`), снимает экран (DXGI Desktop Duplication, если адаптер отказывает — GDI BitBlt), меняет громкость (Core Audio), жмёт клавиши медиа, открывает ярлык меню «Пуск» (`ShellExecuteW`), читает буфер и выполняет сон, блокировку, перезагрузку и выключение. Уведомления Центра уведомлений обычная программа прочитать не может, список на телефоне пустой. На macOS управление по-прежнему через AppleScript, `screencapture` и CoreGraphics; `osascript` там остаётся для громкости, Spotify, запасного ввода текста, перезагрузки и выключения. Мышь на Mac идёт через вспомогательный Python. Нативный помощник для Mac на этой машине не собирался: здесь нет Xcode. Получатель файлов в `pult.exe` — папка «Загрузки\Pult», до 1 ГБ. Полный FlyDrop с подтверждением устройства остаётся в агенте Node. У Mac в интерфейсе написано «FlyDrop для Mac — скоро».

Один запущенный агент — один компьютер. PWA в демо-режиме (`--mock` или тестовый стенд) рисует ещё MacBook Pro и спящий mac-mini локально, чтобы были все девять экранов. Настоящие несколько компьютеров одновременно — это нативное приложение: оно ищет `_pult._tcp` и держит отдельное сопряжение с каждым.

## Агент на Windows

Запускайте `pult.exe`, не `node src\index.js`. Windows считает файл `.js` сценарием JScript. Правило Kaspersky «Запуск Windows PowerShell из скрипта JScript» срабатывает на такую цепочку, даже если сам Пульт ничего вредоносного не делает. Один обычный exe этой эвристике не подходит: так устроены TeamViewer, AnyDesk и Parsec.

Почему Go, а не помощник рядом с Node: помощник, которого породил `node something.js`, всё равно сидит под сценарием. Отдельный Rust-бинарник здесь не собрать без mingw, а C# NativeAOT с Linux собирается хрупко. Go собирается в один exe командой `CGO_ENABLED=0` прямо на Linux, без упаковщика и без вырезания символов. Внутри exe — HTTPS, та же PWA и тот же протокол v1, что у приложения SwiftUI. Полный сервер FlyDrop в exe не вложен: для этого пришлось бы тащить `node.exe`. Файл с телефона сохраняется в `%USERPROFILE%\Downloads\Pult`.

В консоли будут код из шести цифр, отпечаток сертификата, одна строка `iPhone:` с именем адаптера и QR-код этого адреса. Пока телефон сопряжён, в трее значок «Пульт» и поверх окон табличка «Пульт управляет этим компьютером». Закрытие таблички Пульт не завершает. Телефон и компьютер в одной Wi-Fi.

Полезные флаги: `--name "Windows ПК"`, `--port 4720`, `--no-mdns`, `--no-firewall`, `--data папка`, `--revoke <id>`. Рядом с 4720 всегда открыт 4721.

`node src\index.js` на Windows сразу завершается и **ничего не слушает**. В консоли крупно написано «ПУЛЬТ НЕ ЗАПУЩЕН». Пока на экране эта надпись, iPhone не откроет ни один адрес. Нужен `pult.exe`.

Каталог данных: `%APPDATA%\Pult`. Там список телефонов и сертификат, которому телефон доверяет. Повторный запуск не просит доверять заново.

`node src\index.js` на Windows сразу завершается и печатает, как собрать exe. `--mock` оставлен для репетиции интерфейса и по-прежнему ничего не нажимает на столе. `--node` — только для разработки агента, на рабочий компьютер его не берут.

### Как проверить новую сборку на компьютере с Kaspersky

Здесь Kaspersky нет. Ниже — что уже проверено сборкой, и что нужно нажать на рабочем ПК.

1. Откройте успешный запуск GitHub Actions «Pult Windows» на ветке `cursor/pult-iphone-remote-3490` и скачайте артефакт `pult-windows-amd64`. Внутри неподписанный `pult.exe`. Запуски, которые упали до старта заданий, артефакта не содержат. Подписанный `pult-windows-amd64-signed` появляется только если в секретах репозитория есть сертификат. Либо на самом Windows, где установлен Go 1.27 или новее:

```bat
cd pult
set CGO_ENABLED=0
go build -trimpath -o pult.exe .\win\cmd\pult
```

Не используйте UPX и флаги, которые вырезают символы.
2. Скопируйте `pult.exe` в обычную папку, например «Документы». Не кладите его в архив с паролем и не переименовывайте в `.js` или `.cmd`.
3. Дважды щёлкните `pult.exe`. Окно консоли должно остаться открытым: код, адрес, адаптер, QR. В трее появляется «Пульт».
4. Если сеть частная и прав не хватило, консоль попросит один раз запустить тот же exe правым щелчком → «Запуск от имени администратора». Пульт сам повышение не запрашивает и общедоступный профиль не открывает. Защиту антивируса не отключайте и исключения не добавляйте.
5. На iPhone сначала откройте `http://адрес:4721/setup` (QR над ним в консоли). Установите профиль и включите доверие. Проверка: `http://адрес:4721/ping` показывает `ok`. Затем откройте `https://адрес:4720/`, введите шесть цифр, нажмите «Управлять».
6. Проверьте картинку экрана, тачпад, клавиатуру, громкость, буфер, блокировку и ярлык из меню «Пуск». Правило «Запуск Windows PowerShell из скрипта JScript» появиться не должно: PowerShell Пульт не запускает.
7. Неподписанный новый exe Windows и Kaspersky могут отдельно спросить про репутацию незнакомого файла. Это другое окно, не то правило. Его снимает подпись и заявка в allowlist, а не выключение защиты.

## PWA на iPhone с этого Windows

1. Запустите `pult.exe`, как выше. Не закрывайте окно: в нём код.
2. На iPhone откройте Safari и введите адрес из строки `iPhone:` или отсканируйте QR под ней. Рядом написано имя адаптера, обычно `Wi-Fi` или `Ethernet`. Не открывайте адреса из блока «виртуальные или локальные адаптеры».
3. Сначала откройте `http://192.168.x.x:4721/setup` — обычный HTTP, предупреждения о сертификате ещё нет. Скачайте профиль (`.mobileconfig`) либо `ca.cer`. Установите профиль в «Настройки», затем включите доверие: Настройки → Основные → Об этом устройстве → Доверие сертификатов. В профиле только локальный сертификат, без VPN. Адрес `http://192.168.x.x:4721/ping` должен показать `ok`.
4. После доверия откройте `https://192.168.x.x:4720/`, введите шесть цифр с экрана Windows. Без кода кнопки управления не работают.
5. Поделиться → На экран «Домой». Иконка «Пульт» открывается отдельно от Safari. Web Push и значок на иконке iOS отдаёт только такому приложению, не вкладке Safari.
6. Сверьте отпечаток на экране телефона с отпечатком в консоли Windows, если Safari показывает его в сведениях сертификата.
7. Файл: «Добавить» или лоток «Недавние на iPhone», затем перетащите на карточку Windows. Лимит FlyDrop — 1 ГБ, папка уходит zip без сжатия. Карточка Mac ответит «FlyDrop для Mac — скоро».
8. «Держать на блокировке» на экране сценариев включает тихий звук и Media Session, чтобы iOS могла показать карточку на экране блокировки. Это не Dynamic Island.

Чтобы забыть телефон: `pult.exe --revoke <id>` или удалите `%APPDATA%\Pult`.

## Если Safari пишет, что соединение потеряно

Так бывает, когда в браузер попал адрес виртуального адаптера. Docker, WSL, Hyper-V, VirtualBox и VMware получают свои `192.168.*` и `172.16–31.*`, а `169.254.*` — это сеть без роутера. iPhone их не видит.

Пульт печатает один основной адрес: адаптер Wi-Fi или Ethernet, у которого есть шлюз по умолчанию, и его имя. Адреса vEthernet, WSL, Docker, Hyper-V, VirtualBox, VMware и `169.254` уходят в отдельный список и в QR не попадают. Объявление в локальной сети уходит только с выбранного адреса.

Оба устройства должны быть в одной Wi-Fi. Гостевая сеть и VPN на компьютере прячут его от телефона.

На Windows `pult.exe` добавляет входящее правило TCP портов 4720 и 4721 через API брандмауэра `INetFwPolicy2` (класс `HNetCfg.FwPolicy2`), только для частного профиля. Общедоступную и доменную сеть Пульт не открывает: Параметры → Сеть и Интернет → Wi-Fi → ваша сеть → Частная. После смены профиля запустите `pult.exe` ещё раз или подождите: окно само перепечатает адрес, если сеть сменилась. Пропустить шаг: `pult.exe --no-firewall`. Команду `netsh` Пульт не запускает.

Сервер слушает `0.0.0.0`, не localhost. При старте окно печатает привязку, выбранный адаптер, профиль сети, правило брандмауэра и результат запроса с компьютера на свой `http://адрес:4721/ping`.

### Если iPhone не открывает ни адрес, ни /setup

Запрос тогда не доходит до программы. Частые причины на рабочем компьютере:

- Запущен `node src\index.js`. Он на Windows сразу выходит, порты пустые. Нужен `pult.exe`.
- Сеть общедоступная или доменная. Правило частного профиля на неё не действует, Windows отбрасывает входящие.
- Kaspersky, сетевой экран или «Мониторинг сетевых атак», молча режет входящие на незнакомый порт. Защиту не отключайте и исключения «в обход» не ищите. Если всплыло окно про `pult.exe` — разрешите ему входящие. Если окна не было, откройте отчёт сетевого экрана Kaspersky и разрешите программе сеть.
- Корпоративный Wi-Fi с изоляцией клиентов. Телефон и компьютер в одной сети друг друга не видят. Пульт эту настройку точки доступа не обходит.

Запасной путь — точка доступа iPhone. Компьютер сам подключается к телефону:

1. iPhone: Настройки → Режим модема → разрешить другим.
2. Компьютер: подключиться к этой сети Wi-Fi.
3. Параметры Windows → Сеть → эта сеть → Частная.
4. В окне Пульта появится адрес `172.20.10.x`. Если Пульт уже был запущен, адрес перепечатается сам.
5. На том же iPhone откройте `http://172.20.10.x:4721/setup`, затем `http://172.20.10.x:4721/ping` (на экране `ok`), затем https-адрес из консоли.

## Kaspersky, Defender, ESET, Dr.Web

Пульт не отключает антивирус, не просит добавить исключение и не маскируется. Он ведёт себя как обычная программа удалённого управления: один exe с именем компании и продукта, манифест `asInvoker`, осведомлённость о DPI, без упаковки и без обфускации. Экран, ввод, звук, буфер, питание и запуск ярлыка идут прямыми вызовами Win32 и COM внутри этого exe. Сценарии, `powershell.exe`, `cmd.exe`, `wscript`, `cscript`, `mshta` и `rundll32` не запускаются.

| Возможность | Как сделано в pult.exe |
| --- | --- |
| Сопряжение, PWA, QR, адрес Wi-Fi | Сам exe, mDNS `_pult._tcp` |
| Файл с iPhone | `POST /api/upload` в «Загрузки\Pult» |
| Брандмауэр, только частный профиль | `INetFwPolicy2` |
| Экран | DXGI Desktop Duplication, запасной путь GDI BitBlt, JPEG |
| Мышь, тачпад, клавиатура, текст, медиа-клавиши | `SendInput` |
| Громкость и mute | Core Audio `IAudioEndpointVolume` |
| Буфер | `OpenClipboard` / `GetClipboardData` / `SetClipboardData` |
| Сон, блокировка, перезагрузка, выключение | `SetSuspendState`, `LockWorkStation`, `ExitWindowsEx` с привилегией `SeShutdownPrivilege` |
| Список и запуск программ | Ярлыки меню «Пуск», запуск только `ShellExecuteW` по такому ярлыку |
| Уведомления Windows | Не собираются. Центр уведомлений обычной программе недоступен, обхода нет |
| Название трека | Нет. Клавиши плеера работают, строка «сейчас играет» без сценария пустая |

Подпись Authenticode для выпуска обязательна. Пока сертификата нет, сборка его не требует и не падает. Когда сертификат появится в секретах CI, подпись такая:

```bat
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /f pult.pfx /p %PULT_CERT_PASSWORD% pult.exe
```

В GitHub Actions это шаг после `go build`, только если секрет `PULT_CERT_PFX` задан.

Если неподписанный exe всё же попал в карантин как незнакомый файл, это заявка на ложное срабатывание, а не повод ослаблять защиту:

- Kaspersky: программа allowlist для разработчиков, https://support.kaspersky.com/14666 (заявка на доверенное приложение) и форма ложного срабатывания на сайте Kaspersky.
- Microsoft: Windows Defender Security Intelligence, отправка файла на https://www.microsoft.com/wdsi/filesubmission .

Установщик MSI или Inno Setup — следующий шаг, не эта сборка. Он поставит exe в «Program Files», ярлык и правило брандмауэра на этапе установки. Пока достаточно одного `pult.exe`.

## Что из «живого островка» умеет сайт

Проверено здесь: Chrome 154, headless, Linux, агент в `--mock`, страница открыта по HTTPS с тем же сертификатом. iPhone в этой среде нет. Строки про iOS — ожидаемое поведение WebKit по документации Apple, а не прогон на устройстве.

| Приём | Chrome на этой машине | iOS Safari / экран «Домой» |
| --- | --- | --- |
| Service Worker, оболочка без кэша загрузок | Зарегистрировался, кэш `pult-shell-v1` | Работает у установленного PWA |
| Web Push (VAPID, один `topic` на прогресс) | API есть. Доставку с сервера Apple/FCM отсюда не отправляли: нет разрешения и нет установленной иконки | С iOS 16.4 только у иконки на экране «Домой», после разрешения. Вкладка Safari push не получает. Замена прошлого уведомления тем же `topic` / `tag` ожидается, здесь не подтверждалась на телефоне |
| Badging API | `setAppBadge` принял число (в прогоне было «значок 6»). Иконки рабочего стола у headless нет, поэтому сам значок не виден | С iOS 16.4 у иконки на экране «Домой». В обычной вкладке — нет |
| `new Notification()` | API есть, разрешения headless не дал | На iOS не работает. Снаружи страницы видны только push-уведомления установленного PWA |
| Screen Wake Lock | Пока открыт тачпад, запрос прошёл: «экран не гаснет, пока Пульт открыт» | Только пока страница видима. На заблокированном экране блокировка снимается |
| Media Session + тихий WAV | Метаданные заданы, `audio.play()` тишины прошёл: «играет тишина, карточка может быть на блокировке». Карточку самой блокировки Chrome не показывает | Карточка «играет» на экране блокировки возможна, только если iOS не остановит тихий звук. Это не островок и не Live Activity. Жесты play/pause доходят, если система оставила сессию |
| Background Sync | `SyncManager` в Chrome есть. Регистрация `pult-flush` делается вместе с подпиской на push; в прогоне кнопку push не нажимали | В WebKit нет |
| Web Share Target | В манифесте есть `POST /share`. Приём multipart покрыт тестом агента. Системную шторку «Поделиться» headless не открывает | В WebKit манифестный share target не реализован. На iPhone файл берётся кнопкой «Добавить» |
| Выбор файла и перетаскивание на карточку | Проверено кликами: лоток подсветил Windows, файл дошёл до входящих FlyDrop | Выбор файла работает. Перетаскивание зависит от того, отдаст ли iOS жест странице |
| Dynamic Island, Live Activity, виджет блокировки | Не существуют для сайта. В интерфейсе есть чёрная полоска и экран «блокировка» — это рисунок | Только нативное приложение, `pult/ios` |
| Несколько компьютеров по-настоящему | В демо карточки Mac живут в странице. Команды им не уходят на другой агент | То же ограничение одного origin. Несколько агентов — нативный клиент |

Полоска сверху PWA повторяет split-вид макета (процент и нота). Сайт не может нарисовать системный Dynamic Island.

## Приложение на Mac

Нужны Mac, Xcode 15 (iOS 17) и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```sh
cd pult/ios
xcodegen generate
open Pult.xcodeproj
```

Схема `Pult` запускает симулятор с аргументом `-PultMock`: три компьютера из макета, без сети. Кнопка «Открыть демо без компьютера» делает то же самое. Без мока приложение ищет `_pult._tcp`, спрашивает адрес и шесть цифр, запоминает отпечаток сертификата и дальше отвергает другой сертификат.

Live Activity и Dynamic Island — `ActivityKit` в расширении `PultWidgets`. Виджет «Компьютеры» — прямоугольник экрана блокировки, строка и маленький виджет. Снимок пишется в App Group `group.app.flydrop.pult`. Без включённой группы в подписи виджет останется на запасном примере.

Сборку iOS на Linux не запускали: здесь нет Xcode и iOS SDK. Пакет `pult/protocol` собран Swift 6.0.3, `swift test` проходит: команды, кадр, zip-байты совпадают с агентом.

Файл в нативном приложении выбирается через системный импорт и уходит в FlyDrop по его HTTPS (`/api/connect`, ожидание подтверждения, `/api/upload`). Отдельного Share Extension нет: пункт «Поделиться → Пульт» в системной шторке iOS не появится.

## Что уже есть и чего нет

Есть: сопряжение, LAN-ограничение, превью, тачпад, клавиатура, громкость, медиа, список и запуск приложений, буфер, питание с удержанием, Wake-on-LAN и сценарий на 03:00, приём файла существующим FlyDrop, PWA со всеми девятью экранами, набросок нативного клиента с ActivityKit и WidgetKit, тесты агента и пакета протокола.

Проверено здесь, на Linux: тесты протокола и агента Node, тесты Go (`go test ./...` в `pult`), кросс-компиляция `pult.exe` для `windows/amd64`. Исходники Windows-пути не содержат запуска сценариев. Вызовы Win32, DXGI, Core Audio и COM брандмауэра на этой машине не исполнялись: здесь нет Windows и нет Kaspersky.

Нужно на рабочем ПК с Kaspersky: двойной щелчок по `pult.exe`, картинка экрана, мышь, клавиатура, громкость, буфер, блокировка, ярлык меню «Пуск», правило частной сети и отсутствие окна «Запуск Windows PowerShell из скрипта JScript». Репутация неподписанного exe — отдельный вопрос, он закрывается подписью и заявкой в allowlist.

Нет и честно не проверено: сборка и симулятор Xcode, любой прогон на настоящем iPhone, push доставленный на iOS, фоновые уведомления Windows из Центра уведомлений, FlyDrop на Mac, живой Kaspersky, Defender ASR, ESET и Dr.Web.

```sh
node --test --test-concurrency=1 pult/agent/test/*.test.js
node --test test/*.test.js
cd pult && go test ./...
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -o dist/pult.exe ./win/cmd/pult
```

Протокол:

```sh
swift test --package-path pult/protocol
```

Экраны PWA и прокликивание (нужен Chrome):

```sh
node pult/agent/scripts/shots.mjs
```
