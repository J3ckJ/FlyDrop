# Пульт

iPhone управляет Mac и Windows в своей Wi-Fi и отправляет файлы в FlyDrop. Здесь два клиента и один агент.

1. **PWA** — основной клиент. Его отдаёт агент по HTTPS, как FlyDrop отдаёт свой веб-клиент. Открывается в Safari и ставится на экран «Домой».
2. **Приложение SwiftUI** — тот же протокол, плюс настоящие Live Activity (ActivityKit) и виджеты экрана блокировки (WidgetKit).

Интерфейс на русском и повторяет макет `design/WHATS_NEW.md`: чёрный фон, стекло только у поиска, таб-бара, плавающих кнопок и шторки. Зелёный — компьютер в сети, янтарный — спит, синий — идёт передача, красный — только «Выключить».

## Как устроено

Агент — Node.js 22, тот же runtime, что у FlyDrop, без нативных модулей. Так его можно запустить на Windows и macOS одной командой `node`.

- Управление идёт по WebSocket `wss://компьютер:4720/pult` поверх TLS-сертификата FlyDrop (ECDSA P-256, только частные IPv4 и localhost).
- Кадр экрана — отдельное бинарное сообщение: байт `0x01`, длина JSON-заголовка, `{seq,width,height}`, затем JPEG. Не больше 12 кадров/с.
- Обнаружение — объявления mDNS `_pult._tcp.local`. В TXT нет кода сопряжения, только ОС, версия, короткий отпечаток и порт FlyDrop.
- Сопряжение — шесть цифр на экране компьютера, один раз. После успеха код меняется. Пять ошибок с одного адреса за минуту останавливают попытки. Ключ телефона хранится как SHA-256.
- Несопряжённый сокет может только представиться и ввести код. Адрес вне локальной сети (и CGNAT `100.64.0.0/10`) соединение не получает.
- Выключение принимается только с `hold: true`. Если FlyDrop ещё передаёт файл, выключение и перезагрузка не выполняются, пока телефон не пришлёт `force: true`.
- Общий разбор команд лежит в `protocol/` и проверяется `swift test` на Linux. Тот же набор команд проверяет агент.

FlyDrop не переписан. Агент встраивает `createApp` из корня репозитория. Если порты 4317/4318 уже заняты живым FlyDrop, агент не поднимает второй и не подтверждает устройства сам: телефон нужно подтвердить в окне FlyDrop. Пока FlyDrop внутри Пульта, агент держит получателя «в сети» и подтверждает телефон только если запрос пришёл с адреса уже сопряжённого Пульта.

PWA не может сама выставить заголовок `Origin` на чужой порт, а FlyDrop требует его. Поэтому загрузка из PWA идёт на `/api/upload` того же сайта, а агент пересылает тело в FlyDrop. Нативное приложение говорит с FlyDrop напрямую: код и `hostId` приходят в `hello` после сопряжения.

На Windows агент двигает мышь и клавиатуру, снимает экран, меняет громкость, жмёт клавиши медиа, читает меню «Пуск», буфер и выполняет сон, блокировку, перезагрузку и выключение. На macOS то же через AppleScript, `screencapture` и CoreGraphics; для ввода нужна вспомогательная программа и разрешение на запись экрана. Получатель FlyDrop по-прежнему Windows. У Mac в интерфейсе написано «FlyDrop для Mac — скоро».

Один запущенный агент — один компьютер. PWA в демо-режиме (`--mock` или тестовый стенд) рисует ещё MacBook Pro и спящий mac-mini локально, чтобы были все девять экранов. Настоящие несколько компьютеров одновременно — это нативное приложение: оно ищет `_pult._tcp` и держит отдельное сопряжение с каждым.

## Агент на Windows

Нужен Node.js 22.12 или новее.

```bat
cd FlyDrop
npm ci
cd pult\agent
npm ci
node src\index.js
```

Либо `pult\agent\Start-Pult.cmd`. В консоли будут код из шести цифр, отпечаток сертификата и строка `https://192.168.x.x:4720/`. Телефон и компьютер в одной Wi-Fi. Для безопасной репетиции без управления настоящим столом: `node src\index.js --mock`.

Полезные флаги: `--name "Windows ПК"`, `--port 4720`, `--no-mdns`, `--data папка`, `--revoke <id>` (снять сопряжение).

Каталог данных: `%APPDATA%\Pult`. Там список телефонов и ключи Web Push.

## PWA на iPhone с этого Windows

1. Запустите агент на Windows, как выше. Не закрывайте окно: в нём код.
2. На iPhone откройте Safari и введите адрес из строки `iPhone:` — `https://192.168.x.x:4720/`. Не `http://` и не адрес из интернета.
3. Safari покажет предупреждение о сертификате. Откройте `https://192.168.x.x:4720/setup` и скачайте профиль (`.mobileconfig`) либо `ca.cer`. Установите профиль в «Настройки», затем включите доверие сертификату: Настройки → Основные → Об этом устройстве → Доверие сертификатов. Это тот же приём, что у FlyDrop: в профиле только локальный сертификат, без VPN.
4. Вернитесь на `https://192.168.x.x:4720/`, введите шесть цифр с экрана Windows. Без кода кнопки управления не работают.
5. Поделиться → На экран «Домой». Иконка «Пульт» открывается отдельно от Safari. Web Push и значок на иконке iOS отдаёт только такому приложению, не вкладке Safari.
6. Сверьте отпечаток на экране телефона с отпечатком в консоли Windows, если Safari показывает его в сведениях сертификата.
7. Файл: «Добавить» или лоток «Недавние на iPhone», затем перетащите на карточку Windows. Лимит FlyDrop — 1 ГБ, папка уходит zip без сжатия. Карточка Mac ответит «FlyDrop для Mac — скоро».
8. «Держать на блокировке» на экране сценариев включает тихий звук и Media Session, чтобы iOS могла показать карточку на экране блокировки. Это не Dynamic Island.

Чтобы забыть телефон: `node src\index.js --revoke <id>` или удалите `%APPDATA%\Pult`.

## Что из «живого островка» умеет сайт

Проверено здесь: Chrome 154, headless, Linux, агент в `--mock`, страница открыта по HTTPS с тем же сертификатом. iPhone в этой среде нет. Строки про iOS — ожидаемое поведение WebKit по документации Apple, а не прогон на устройстве.

| Приём | Chrome на этой машине | iOS Safari / экран «Домой» |
| --- | --- | --- |
| Service Worker, оболочка без кэша загрузок | Зарегистрировался, кэш `pult-shell-v1` | Работает у установленного PWA |
| Web Push (VAPID, один `topic` на прогресс) | API есть. Доставку с сервера Apple/FCM отсюда не отправляли: нет разрешения и нет установленной иконки | С iOS 16.4 только у иконки на экране «Домой», после разрешения. Вкладка Safari push не получает. Замена прошлого уведомления тем же `topic` / `tag` ожидается, здесь не подтверждалась на телефоне |
| Badging API | `setAppBadge` принял число (в прогоне было «значок 6»). Иконки рабочего стола у headless нет, поэтому сам значок не виден | С iOS 16.4 у иконки на экране «Домой». В обычной вкладке — нет |
| `new Notification()` | API есть, разрешения headless не дал | На iOS не работает. Снаружи страницы видны только push-уведомления установленного PWA |
| Screen Wake Lock | Пока открыт тачпад, запрос прошёл: «экран не гаснет, пока Пульт открыт» | Только пока страница видима. На заблокированном экране блокировка снимается |
| Media Session + тихий WAV | Метаданные заданы, `audio.play()` тишины прошёл: «играет тишина, карточка может быть на блокировке». Карточку самой блокировки Chrome не показывает | Карточка «играет» на экране блокировки возможна, только если iOS не остановит тихий звук. Это не островок и не Live Activity. Жесты play/pause доходят, если система оставила сессию |
| Background Sync | `SyncManager` в Chrome есть. Регистрация `pult-flush` делается вместе с подпиской на push; в прогоне кнопку push не нажимали | В WebKit нет |
| Web Share Target | В манифесте есть `POST /share`. Приём multipart покрыт тестом агента. Системную шторку «Поделиться» headless не открывает | В WebKit манифестный share target не реализован. На iPhone файл берётся кнопкой «Добавить» |
| Выбор файла и перетаскивание на карточку | Проверено кликами: лоток подсветил Windows, файл дошёл до входящих FlyDrop | Выбор файла работает. Перетаскивание зависит от того, отдаст ли iOS жест странице |
| Dynamic Island, Live Activity, виджет блокировки | Не существуют для сайта. В интерфейсе есть чёрная полоска и экран «блокировка» — это рисунок | Только нативное приложение, `pult/ios` |
| Несколько компьютеров по-настоящему | В демо карточки Mac живут в странице. Команды им не уходят на другой агент | То же ограничение одного origin. Несколько агентов — нативный клиент |

Полоска сверху PWA повторяет split-вид макета (процент и нота). Сайт не может нарисовать системный Dynamic Island.

## Приложение на Mac

Нужны Mac, Xcode 15 (iOS 17) и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```sh
cd pult/ios
xcodegen generate
open Pult.xcodeproj
```

Схема `Pult` запускает симулятор с аргументом `-PultMock`: три компьютера из макета, без сети. Кнопка «Открыть демо без компьютера» делает то же самое. Без мока приложение ищет `_pult._tcp`, спрашивает адрес и шесть цифр, запоминает отпечаток сертификата и дальше отвергает другой сертификат.

Live Activity и Dynamic Island — `ActivityKit` в расширении `PultWidgets`. Виджет «Компьютеры» — прямоугольник экрана блокировки, строка и маленький виджет. Снимок пишется в App Group `group.app.flydrop.pult`. Без включённой группы в подписи виджет останется на запасном примере.

Сборку iOS на Linux не запускали: здесь нет Xcode и iOS SDK. Пакет `pult/protocol` собран Swift 6.0.3, `swift test` проходит: команды, кадр, zip-байты совпадают с агентом.

Файл в нативном приложении выбирается через системный импорт и уходит в FlyDrop по его HTTPS (`/api/connect`, ожидание подтверждения, `/api/upload`). Отдельного Share Extension нет: пункт «Поделиться → Пульт» в системной шторке iOS не появится.

## Что уже есть и чего нет

Есть: сопряжение, LAN-ограничение, превью, тачпад, клавиатура, громкость, медиа, список и запуск приложений, буфер, питание с удержанием, Wake-on-LAN и сценарий на 03:00, приём файла существующим FlyDrop, PWA со всеми девятью экранами, набросок нативного клиента с ActivityKit и WidgetKit, тесты агента и пакета протокола.

Нет и честно не проверено: сборка и симулятор Xcode, любой прогон на настоящем iPhone, push доставленный на iOS, фоновые уведомления Windows из Центра уведомлений (агент пересылает события FlyDrop, не тосты системы), FlyDrop на Mac, управление, если на Windows уже запущен отдельный FlyDrop.exe (тогда подтверждение ручное).

## Проверки

Из корня репозитория, при установленном `pult/agent/node_modules`:

```sh
node --test --test-concurrency=1 pult/agent/test/*.test.js
node --test test/*.test.js
```

Протокол:

```sh
swift test --package-path pult/protocol
```

Экраны PWA и прокликивание (нужен Chrome):

```sh
node pult/agent/scripts/shots.mjs
```

Снимки появляются в `pult/preview/shots/`.
